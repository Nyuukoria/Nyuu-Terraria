# v0.4.0 validation

The mod compiled with no errors or warnings against the installed tModLoader 1.4.5-dev build `25921d5f` (2026-11-06).

An isolated dedicated-server test copy passed 25 focused checks: five-profession persistence through switching and binary save/load; quest/profile/appearance persistence; consuming gathering materials; preventing duplicate rewards; resolving all 12 quest rewards; backpack slots 0 and 99 persistence; backpack input without a container; main-tab hiding and Equipment-tab visibility; the scrollbar patch matching the installed loader; creating and reloading both realms without overlap; ore and persistent loot chests; entering/returning through the portal; Hardmode gating; four encounter attack-loop smoke tests across both health phases; world-coordinate serialization; panel/mouse alignment across four UI scales; restoring input state after UI updates; and preventing journal/backpack overlap.

Every packaged item, NPC, projectile, tile, buff, and hair texture path was checked. All 68 expedition PNG files decoded successfully and had binary alpha with no partial white fringes. Worn rig files and hairstyle alternate sheets are included.

The isolated rendered client stopped at Steam initialization. The final in-game layout, worn animation alignment, multiplayer gameplay, and balance have not been visually/playthrough verified. Attack-loop tests verify that the code runs, not that a fight is balanced or enjoyable.

## Running the test fixture

`ChronicleChecks.cs` is a test-only ModSystem. Copy the mod source to an isolated test folder, add this fixture under that copy's `Content` directory, and build it into a separate mod save directory. Load a disposable copied test world with that mod on a dedicated server. The fixture records checks in `NyuuTerraria-validation.txt` under the test save directory, saves realm state, and exits the process after success. Run it again with that test world to verify world reloads. A failed check throws with its name.

Do not include this fixture in the normal mod build: it creates test state and exits after testing. The distributed release contains no test fixture.
