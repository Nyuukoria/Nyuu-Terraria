# v0.4.1 validation

## Build and assets

Compiled against tModLoader 1.4.5-dev build `25921d5f` (2026-11-06), with zero errors and warnings. Release and tests use separate save directories. No original player saves or worlds are used by the tests.

All 191 mod content texture references resolved in the packaged test mod. The 14 new Spellcraft PNGs decode, contain visible pixels, and use binary alpha without partially transparent matte fringes. The sprite contact sheet was inspected; this does not verify the in-game rendered effects.

## Isolated logic checks

A dedicated-server fixture completed 257 assertions: 191 asset-path checks, 25 existing Chronicle checks, and 41 new mage checks. The mage checks cover:

- Default and locked spells, one-time tome learning, separate character arrays, bounded invalid save values, and binary character save/load.
- Switching spells without losing XP, pre-Hardmode/Hardmode mastery caps, and retaining advanced mastery when visiting an earlier world.
- Healing amount, cooldown, and refusing full-health casts.
- Preserving a magic reforge's base item stats across all six casting modes.
- Same-tick hit XP limiting and statue-enemy exclusion.
- Ward front/back filtering, important/heavy projectile exclusions, actual blocking, recovery, stopping without mana, sigil cost reduction, and clearing accessory effects.
- Offensive projectile travel, stronger charged Ember release, canceling a charge on spell swap, lightning chaining, nonrecursive water fragments, Wet, and the explosion's damage window.

The existing checks cover profession/quest/profile persistence, quest rewards, backpack persistence and Equipment-tab placement, inventory input, four UI scales, the accessory-scroll patch, realm reload/travel/ore/loot, world serialization, and encounter attack loops.

The mana shutdown check exposed a dev-loader difference: its integer-only `CheckMana` overload can allow zero-mana casting under the loader's experimental mana behavior. The new held casts use the item-aware overload, with a minimum continuing payment of one mana.

## Test runner and limitations

`tests/ChronicleChecks.cs` and `tests/SpellcraftChecks.cs` are test-only fixtures. Copy both into an isolated source copy's `Content` directory and build using a separate mod save directory. Load a disposable copied test world. The fixture modifies test state, saves the test world, and exits the process. It must never be included in a normal playable release. Exceptions are written to a test failure file and exit with code 1, avoiding the engine's console-input crash dialog.

The fake server player is initialized without a normal player update, so the fixture sizes its projectile counters and initializes its mana multiplier explicitly. Outbound mod packets are intercepted during the mage tests because no live client socket exists during `PostWorldLoad`; actual server combat logic still executes. These checks do not prove multiplayer synchronization. Existing realm travel smoke checks emit headless map/network warnings before completing; they are not a clean multiplayer playthrough.

Rendered client testing previously stopped at Steam initialization. UI appearance, animation alignment, spell rendering, real multiplayer play, and balance remain unverified. A successful attack-loop smoke check does not prove a fair or enjoyable encounter.
